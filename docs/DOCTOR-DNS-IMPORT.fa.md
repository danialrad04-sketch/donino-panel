# کاتالوگ و انتقال مرحله‌ای doctor-dns

در alpha 7، دادهٔ کاتالوگ پروژهٔ [doctor-dns شما](https://github.com/danialrad04-sketch/doctor-dns) در commit `a2b2ff843cb1fc8f0a5712a88149f5c379198ff1` به Donino اضافه شده است: ۴۲ سرویس، ۴۸ گروه و ۵۰۵ دامنه. منبع اصلی [mehdi047/doctor-dns](https://github.com/mehdi047/doctor-dns)، متن MIT و checksum داده در `deploy/catalogs/` حفظ شده‌اند. کد نصب، firewall، relay و پنل doctor-dns اجرا یا با برنامهٔ Donino مخلوط نشده‌اند.

## ساخت سیاست از کاتالوگ

در بخش DNS، «از کاتالوگ سرویس‌ها» را بزنید، گروه‌های دلخواه و IPهای relay تحت اختیار خود را بدهید. یک سیاست مستقل با قواعد rewrite ساخته می‌شود؛ استثناهای مستقیم به allow تبدیل می‌شوند. قواعد پسوندی و اولویت دامنهٔ دقیق‌تر مطابق [راهنمای DNS](DNS-PREVIEW.fa.md) است. بدون آدرس IPv6، پاسخ AAAA آن دامنه بازنویسی‌شده NODATA است تا آدرس واقعی از همان پاسخ مسیر جایگزین نسازد.

این عملیات **relay نصب نمی‌کند** و سیاست را خودکار به کاربری اختصاص نمی‌دهد. کاتالوگ، دادهٔ دامنه است؛ وضعیت بازی/فروشگاه/دانلود روی ISP واقعی برای تمام این سرویس‌ها آزموده‌نشده است. حذف یک دامنهٔ والد از مسیر به معنی غیرفعال‌کردن تمام قواعد دقیق‌تر نیست؛ استثناها را با توجه به اولویت پسوند بازبینی کنید. منابع و نسخهٔ این داده ثابت‌اند و دریافت خودکار فهرست ناشناخته وجود ندارد.

## انتقال حساب‌ها

ابزار محلی، snapshot سازگار SQLite را از منبع **فقط‌خواندنی** می‌گیرد؛ کد منبع را import یا execute نمی‌کند. نام/تعداد جدول‌ها، مقادیر مهم، شکل hash شناخته‌شدهٔ PBKDF2-SHA256/salt، مالکیت IP و کلیدهای service/group بررسی می‌شوند. hash یا گروه ناشناخته، IP مبهم، جدول ناشناخته و فایل خراب رد می‌شوند. تشخیص فرمت به معنی اثبات رمز کاربران یا اصالت فایل نیست؛ فقط backup تحت اختیار خود را منتقل کنید. این برش حداکثر ۶۴ MiB فایل SQLite، ۱۰۰ هزار ردیفِ منتقل‌شونده و snapshot با مهلت محدود را می‌پذیرد.

ابتدا پیش‌نمایش، بدون نوشتن در DB مقصد:

```bash
python -m ops.doctor_import inspect /secure/doctor-panel.db
```

خروجی شامل شناسهٔ پیشنهادیِ منبع، fingerprint، تعداد حساب/قالب/IP/رسید و جمع حجم و مصرف است؛ hash رمز، نشست یا تصویر رسید چاپ نمی‌شود. شناسهٔ همان منبع و fingerprint همان بررسی را در اجرای بعدی استفاده کنید:

```bash
python -m ops.doctor_import apply /secure/doctor-panel.db \
  --source-instance UUID_FROM_INSPECTION \
  --expected FINGERPRINT_FROM_INSPECTION \
  --backup /secure/before-doctor-import.db
```

برای نصب managed، دستور را با Python محیط نصب‌شده و متغیرهای `/etc/donino/panel.env`، در چارچوب کاربر/سرویس مجاز اجرا کنید؛ همان الگوی `systemd-run` ابزارهای محلی installer قابل استفاده است. فایل env و رمز DB را در خط فرمان، issue یا پیام منتشر نکنید. در PostgreSQL، خروجی backup از نوع archive همان backend است؛ نام `.dump` روشن‌تر است. فایل backup نباید از قبل وجود داشته باشد. شکست backup مانع ایجاد رکورد وارداتی می‌شود.

حساب‌های Donino و دستگاه پیش‌فرض آن‌ها **غیرفعال** ساخته می‌شوند. فعال‌سازی از API معمول کاربران نیز تا مرحلهٔ تطبیق پشتیبانی نمی‌شود. کلیدهای جدید Donino مستقل‌اند؛ رمز VPN یا نشست‌های doctor-dns دوباره استفاده نمی‌شوند. مصرف/حجم بایتی Smart DNS، دوره، تاریخ انقضا، وضعیت، template، سرعت، محدودیت IP، کیف پول، رسیدها و شمارنده‌های مبدأ در انتقال حفظ می‌شوند؛ دادهٔ خصوصی در آرشیو رمزگذاری‌شده ذخیره می‌شود. اطلاعات عملیاتی قابل مشاهده، مانند حجم و مصرف مبدأ، در metadata مرحلهٔ انتقال هم وجود دارند.

هیچ IP قدیمی خودکار مجاز نمی‌شود؛ باید از اتصال واقعی دوباره اثبات شود. بایت Smart DNS به درخواست DNS یا مصرف VPN تبدیل نمی‌شود. ماندهٔ کیف پول، سرعت، hash رمز و تنظیمات مبدأ خودکار فعال نمی‌شوند. نشست‌های مدیر/کاربر و metrics موقت منتقل نمی‌شوند؛ تعداد حذف‌شده در گزارش مشخص است. این **انتقال مرحله‌ای** است؛ جایگزینی فعال سرویس doctor-dns به relay/exit، دفتر ترافیک و پذیرش بعدی نیاز دارد.

تکرار همان snapshot با همان شناسهٔ منبع، حساب جدید نمی‌سازد. تغییر snapshot یا استفادهٔ دوباره از منبعی که بازگردانده شده، نیازمند تصمیم مهاجرت صریح است؛ برای retry شناسهٔ تازه تولید نکنید.

## مشاهده و بازگشت

مالک در بخش DNS، «مشاهدهٔ انتقال‌ها» را می‌بیند. APIهای owner-only زیر فقط metadata دارند، نه آرشیو رمزها و رسیدها:

```text
GET /api/imports/doctor
GET /api/imports/doctor/{id}/users
GET /api/imports/doctor/{id}/templates
```

تا وقتی حساب‌های ساخته‌شده یا دادهٔ وابسته تغییر نکرده‌اند، بازگشت انتخابی ممکن است:

```bash
python -m ops.doctor_import rollback IMPORT_UUID \
  --backup /secure/before-doctor-rollback.db
```

بازگشت، پیش از حذف snapshot می‌گیرد و دوباره داخل تراکنش مالکیت/بدون‌تغییربودن رکوردها را بررسی می‌کند. فقط حساب‌ها و قالب‌های همان انتقال حذف می‌شوند؛ حساب‌های دیگر دست‌نخورده‌اند. اگر نام، اعتبارنامه، تخصیص نود، مصرف یا خدمت DNS وابسته عوض شده باشد، کل بازگشت رد می‌شود و چیزی حذف نمی‌شود. رکورد انتقال، audit و آرشیو رمزگذاری‌شده برای رسیدگی باقی می‌مانند. تکرار بازگشت حساب دیگری را پاک نمی‌کند.

آرشیو خصوصی با کلید مستقل `master.key` موجود رمزگذاری می‌شود. برای بازیابی آن روی میزبان دیگر، backup کامل رمزگذاری‌شدهٔ Donino و کلید جدا را نگه دارید؛ backup صرف DB کافی نیست. فایل SQLite اصلی doctor-dns نیز می‌تواند رمز/رسید/اطلاعات مالی داشته باشد و باید خصوصی بماند. سیاست retention و فعال‌سازی انتقال، همراه مراحل عملیاتی و relay تکمیل می‌شوند.

## خروجی مدیریت‌شده در alpha 11

در کنار فرم قدیمی rewrite، «مسیریابی از کاتالوگ» نود اصلی و دو جایگزین می‌گیرد و قواعد `route` می‌سازد. این مسیر پس از نصب [Smart DNS](SMART-DNS.fa.md)، آزمون/فعال‌سازی خروجی و مجوز/IP حساب قابل استفاده است. انتخاب کاتالوگ، واردات غیرفعال doctor-dns را فعال نمی‌کند؛ حجم تاریخی آن همچنان خودکار به حجم relay تبدیل نمی‌شود.
