# DNS اختصاصی در پیش‌نمایش alpha 6

این نسخه خدمت DNS معمولی و رمزگذاری‌شده را اضافه می‌کند: UDP، TCP، DoT و DoH با سیاست و دفتر مصرف مستقل. این خدمت، ترافیک بازی را تونل نمی‌کند. Smart DNS relay/exit، کاتالوگ بازی‌ها، انتقال doctor-dns و DoQ هنوز تکمیل نشده‌اند. [طراحی DNS گیمینگ](DNS-GAMING-DESIGN.fa.md) هدف مراحل بعد است.

## نصب

روی نصب managed یا میزبان تمیزِ سازگار، از سورس همین انتشار اجرا کنید:

```bash
sudo ./install.sh --domain panel.example.com --with-dns
```

علاوه بر کنترل‌پنل، بسته‌های Unbound و dns-root-data از مخزن امضاشدهٔ توزیع نصب می‌شوند. یک Unbound جدا روی `127.0.0.1:5335` و gateway روی `127.0.0.1:5353` برای UDP/TCP و `127.0.0.1:8530` برای DoT راه می‌افتند. DoH از HTTPS همان پنل و مسیر `/dns-query` می‌آید. حالت پیش‌فرض، UDP/TCP/DoT را روی اینترنت باز نمی‌کند؛ DoH نیز بدون اعتبارنامه پاسخ DNS نمی‌دهد.

برای سرویس عمومیِ مبتنی بر IP اثبات‌شده، آدرس رابط واقعی میزبان و پورت‌های دلخواه را هنگام نصب صریح مشخص کنید:

```bash
sudo ./install.sh --domain panel.example.com --with-dns \
  --dns-listen 0.0.0.0 --dns-port 53 --dot-port 853
```

این نمونه فقط listener IPv4 می‌سازد؛ برای listener IPv6، نشانی IPv6 بدهید. این نسخه هم‌زمان دو آدرس مستقل برای یک gateway نصب نمی‌کند. رسیدن UDP/TCP 53 و TCP 853 از بیرون به فایروال و ارائه‌دهنده بستگی دارد. installer فایروال/SSH یا resolver نامرتبط را متوقف نمی‌کند و پورت اشغال‌شده را رد می‌کند. فقط سرویس پیش‌فرض بستهٔ Unbound که همین نصب تازه معرفی کرده است غیرفعال می‌شود تا با نمونهٔ اختصاصی Donino تعارض نداشته باشد. تنظیمات DNS در نصب دوباره حفظ می‌شوند؛ تغییر آدرس یا پورت هم باید بدون تعارض باشد.

پیش از اجرا می‌توان `plan --domain ... --with-dns` را دید. `repair` تنظیمات managed و سرویس‌ها را بازسازی می‌کند. `uninstall` سرویس‌های Donino DNS و resolver اختصاصی را متوقف و فایل‌های managed را حذف می‌کند؛ DB، کلیدها، نسخه‌ها و backup را نگه می‌دارد. بستهٔ OS و resolver قبلی خارج از مالکیت Donino حذف نمی‌شوند. نقش DNS فعلاً روی همان میزبان کنترل‌پنل اجرا می‌شود؛ نصب و توزیع امضاشدهٔ تنظیمات DNS روی نود دوردست هنوز آماده نیست.

## سیاست و حساب کاربر

در بخش **DNS** یک سیاست بسازید. هر خط یک قاعده دارد:

```text
block example.com
allow allowed.example.com
rewrite service.example.net 1.2.3.4,2001:db8::2
```

قاعده روی دامنه و زیردامنه‌های آن اعمال می‌شود؛ پسوند دقیق‌تر اولویت دارد. `allow` استثنای مسدودسازی است و پاسخ resolver را می‌گیرد. `rewrite` فقط پاسخ A/AAAA متناظر با خانوادهٔ آدرس می‌سازد؛ نوع دیگر NODATA می‌گیرد. آدرس‌های نمونه را با مقصد تحت اختیار خود عوض کنید. بازنویسی برای مقصد relay به‌تنهایی relay ایجاد نمی‌کند.

سپس DNS را برای کاربر فعال و سیاست، سقف درخواست و نرخ را تعیین کنید. صفر در سقف درخواست یعنی نامحدود؛ نرخ مجاز ۱ تا ۱۰۰ درخواست در ثانیه، با پنجرهٔ یک‌ثانیه‌ای است. همهٔ credentialها و IPهای یک حساب همان نرخ/سهمیه را به اشتراک می‌گذارند. اعتبارنامهٔ DoH فقط هنگام ساخت یا چرخش نشان داده می‌شود؛ DB فقط hash آن را نگه می‌دارد. مدیر کاربران می‌تواند حساب DNS را مدیریت کند؛ ساخت/تغییر سیاست فقط برای مالک است.

کاربر در پورتال، سهمیه و IPهای فعال را می‌بیند و می‌تواند اعتبارنامهٔ تازه بسازد. چرخش، اعتبارنامهٔ قبلی را فوراً باطل می‌کند. DoH استاندارد GET/POST و `application/dns-message` را با هدر `Authorization: Bearer dns_…` می‌پذیرد. credential داخل URL پشتیبانی نمی‌شود. مرورگر، کنسول یا برنامه‌ای که هدر اختصاصی DoH ندارد مستقیماً از این روش احراز هویت پشتیبانی نمی‌کند؛ برای آن، روش IP اثبات‌شده یا تونلِ سازگار لازم است. فایل تنظیم همهٔ کلاینت‌ها هنوز عرضه نشده است.

## IP اثبات‌شده و CGNAT

دکمهٔ «ثبت IP همین اتصال» فقط IP عمومیِ اتصال واقعی به پورتال را برای یک ساعت ثبت می‌کند. API زمان ۶۰ ثانیه تا یک روز را می‌پذیرد؛ حداکثر سه IP فعال برای یک حساب مجاز است. ثبت IP دلخواه با پارامتر یا هدر کاربر وجود ندارد. نصب managed، هدرهای پراکسی ورودی را بازنویسی می‌کند و Uvicorn فقط پراکسی loopback را می‌پذیرد. اگر پراکسی دیگری اضافه می‌کنید باید مرز اعتماد را درست تنظیم کنید؛ خاموش‌کردن این بررسی راه‌حل نیست.

UDP/TCP/DoT مالک را از source IP سوکت پیدا می‌کنند. مجوز خالی، منقضی، غیرفعال یا بدون سهمیه، سرویس نمی‌گیرد؛ UDP نامجاز پاسخ ندارد. IPv4-mapped IPv6 به IPv4 یکسان تبدیل می‌شود تا دو مالک برای یک نشانی ساخته نشود. یک IP عمومی نمی‌تواند هم‌زمان به دو حساب تعلق داشته باشد؛ تعارض CGNAT با خطای روشن رد می‌شود. IP به‌تنهایی هویت رمزنگاری‌شده نیست و جعل source در UDP از محدودیت‌های این روش است؛ برای تفکیک کاربران پشت یک IP، DoH احرازشده یا تونل لازم است.

## مصرف، DNSSEC و حریم خصوصی

واحد سهمیه، **تعداد درخواست DNS** است. بایت درخواست/پاسخ، تعداد مسدودسازی و خطا نیز جدا ثبت می‌شوند؛ بایت DNS از حجم VPN کم نمی‌شود و حجم دانلود یا بازی نیست. فعال‌بودن کاربر و انقضای او روی DNS هم اثر دارد؛ تمام‌شدن سهمیهٔ VPN، سهمیهٔ مستقل DNS را مصرف نمی‌کند. خطای upstream نیز یک درخواست انجام‌شده محسوب می‌شود. «دورهٔ تازه» تاریخچه را حفظ می‌کند؛ پاسخ دیررسِ درخواست قبلی در همان دورهٔ قدیم ثبت می‌شود. نام queryها در دفتر مصرف ذخیره نمی‌شود.

Unbound با trust anchor بستهٔ dns-root-data، اعتبارسنجی DNSSEC انجام می‌دهد؛ بسته‌های امنیتی و ساعت میزبان باید به‌روز باشند. Donino فقط به resolver loopback متصل می‌شود. شکست validation، SERVFAIL برمی‌گرداند. پرچم CD استاندارد به resolver منتقل می‌شود. پاسخ block/rewrite و پاسخ‌های تغییرکرده هیچ AD معتبری ادعا نمی‌کنند. سیاست روی CNAME/DNAME و مقصدهای پاسخ نیز بررسی می‌شود؛ کش برحسب شناسه/نسخهٔ سیاست، نام، نوع و پرچم‌های DNSSEC جداست. TTL کش پاسخ منفی از SOA minimum بیشتر نمی‌شود؛ پاسخ UDP برای اندازهٔ مذاکره‌شده truncate می‌شود و upstream truncated از TCP بازیابی می‌شود.

access log پراکسی برای DoH و پورتال غیرفعال است؛ سرویس managed نیز access log مربوط به Uvicorn را خاموش می‌کند. در اجرای دستی هم مراقب URLهای خصوصی اشتراک و queryهای GET باشید. لاگ query/reply در Unbound اختصاصی خاموش است.

گواهی DoT همان گواهی معتبر دامنهٔ پنل است. جفت گواهی/کلید با pipe خصوصی به کاربر محدود سرویس منتقل، پیش از فعال‌سازی تطبیق داده و با pointer اتمی عوض می‌شود؛ شکست جفت جدید، قبلی را دستکاری نمی‌کند. پوشه ۷۰۰ و فایل کلید ۶۰۰ است. تمدید موفق ACME، نسخهٔ DoT را نیز به‌روز و gateway را restart می‌کند؛ اتصال‌های DoT آن لحظه دوباره برقرار می‌شوند. صدور و تمدید عمومی ACME هنوز به VPS/دامنهٔ آزمایشی نیاز دارد.

## حدود پذیرش

آزمون‌ها شامل سهمیه/نرخ هم‌زمان، ابطال، دورهٔ دیررس، سیاست/کش، CNAME، TTL منفی، A/AAAA، TCP fallback و رد IP جعلی/متعارض‌اند. fixture Unbound واقعی، دامنهٔ خصوصی امضاشده و امضای دستکاری‌شده را بررسی می‌کند. fixture نصب، UDP/TCP/DoT و HTTPS واقعی با CA محلی، نصب دوباره و بازیابی حساب DNS را می‌آزماید. این‌ها شاهد ISP/کنسول، ظرفیت تولید، DNSSEC تمام اینترنت یا انتشار پایدار ۱.۰ نیستند.

writer lock سراسری PostgreSQL همچنان وجود دارد؛ ظرفیت DNS با هزاران کاربر اندازه‌گیری نشده است. cache در هر process است و gateway سقف کار هم‌زمان و محدودیت منابع systemd دارد؛ این‌ها جای آزمون بار/حمله نیستند. DoQ، توزیع DNS چندنودی، Smart DNS، فهرست بازی‌های پذیرفته‌شده و importer doctor-dns در مراحل بعد باقی‌اند.
