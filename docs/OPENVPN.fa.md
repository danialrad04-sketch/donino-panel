# OpenVPN UDP/TCP — پیش‌نمایش alpha.15

این نقش مستقل از Xray و WireGuard است و OpenVPN **2.6.x** روی Linux را هدف
می‌گیرد. هر endpoint، CA و tls-crypt مستقل دارد؛ هر دستگاه گواهی، کلید و IP
خود را دارد. کلیدهای خصوصی در DB رمز می‌شوند؛ CA signing key به نود فرستاده
نمی‌شود. فایل خصوصی `.ovpn` فقط توسط مالک پنل دریافت می‌شود و نباید در Git،
گفتگو یا لاگ منتشر شود. حجم، انقضا، دوره و وضعیت حساب با سایر نقش‌ها مشترک
است. حداکثر چهار رابط و ۱۲۸ peer برای هر نود پذیرفته می‌شود. سهمیهٔ lease
پشتیبانی نمی‌شود؛ در چند نود، سهمیهٔ معمول سقف سخت و هم‌زمان بایتی نیست.

## آماده‌سازی نود

نصب این نقش فعلاً دستی است. نسخهٔ یکسان سورس پنل و وابستگی‌های requirements
در `/opt/donino-panel` و `.venv`، بسته‌های OpenVPN 2.6 و iproute2 و دسترسی
`/dev/net/tun` لازم‌اند. عامل بسته یا ماژول کرنل نصب نمی‌کند. برای این نقش
نود و توکن enrollment جدا بسازید؛ اجرای دو عامل با هویت یک نود مجاز نیست.
توکن را در فایل خصوصی با مجوز ۶۰۰ قرار دهید؛ در خط فرمان ننویسید.

```sh
sudo /opt/donino-panel/.venv/bin/python -m agent.enroll \
  --panel https://panel.example.com --node-id NODE_UUID \
  --state /var/lib/donino-openvpn --token-file /root/ovpn-enrollment-token
```

پس از enrollment موفق فایل توکن را حذف کنید. HTTPS پنل بررسی می‌شود؛ برای
CA خصوصی از `--ca-file` استفاده کنید. فایل `/etc/donino/openvpn.env` با
مالک root و مجوز ۶۰۰:

```ini
DONINO_PANEL_URL=https://panel.example.com
DONINO_OVPN_STATE=/var/lib/donino-openvpn
# فقط در صورت نیاز، مسیر مطلق اجرایی:
# DONINO_OPENVPN=/usr/sbin/openvpn
```

```sh
sudo install -m 644 deploy/donino-openvpn.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now donino-openvpn
```

سرویس فقط CAP_NET_ADMIN دارد و runtime خصوصی در StateDirectory نگهداری
می‌شود. سوکت مدیریت Unix خصوصی است و پورت مدیریت عمومی باز نمی‌شود.
ExecStopPost مستقل از دسترسی به پنل، فرایند و رابط متعلق به عامل را متوقف
و شمارنده‌های مشاهده‌شده را در دفتر پایدار ثبت می‌کند. رابط هم‌نام یا PID
بازیافت‌شده پذیرفته نمی‌شود. state حاوی کلید و شمارنده است؛ عمومی نکنید.

اپراتور باید پورت UDP یا TCP انتخابی، forwarding و NAT یا مسیر برگشت را
متناسب با شبکه آماده کند. عامل firewall، sysctl، NAT یا default route
میزبان را تغییر نمی‌دهد. آدرس pool نباید با مسیرهای میزبان، WireGuard یا
رابط‌های دیگر هم‌پوشانی داشته باشد. تداخل پورت با سرویس‌های دیگر را پیش از
فعال‌سازی بررسی کنید؛ عامل سرویس دیگر را متوقف نمی‌کند.

## استفاده و ابطال

در بخش OpenVPN، نود، UDP/TCP، دامنهٔ قابل دسترس، پورت، pool و مسیرها را
انتخاب و endpoint را فعال کنید؛ سپس برای دستگاه حساب، peer بسازید و فایل
ovpn را بدهید. پروفایل mutual TLS، server name pin، AEAD و tls-crypt دارد؛
TLS verification یا بررسی نام را در کلاینت خاموش نکنید. CA اشتباه و نام
سرور اشتباه باید اتصال را رد کنند. ابطال یا rotation با serial گواهی در
عامل اعمال می‌شود؛ داشتن گواهی معتبر از CA به‌تنهایی اجازهٔ ورود نمی‌دهد.

لغو peer، انقضا و پایان سهمیه، نشست جاری را قطع می‌کنند؛ حذف سادهٔ peer
اتصال دستگاه دیگر را نگه می‌دارد. تعویض گواهی، تغییر ساختاری یا ریست دوره
می‌تواند رابط‌های عامل را بازسازی کند و به اتصال مجدد کلاینت‌ها نیاز داشته
باشد. پس از rotation فایل تازه بدهید. restore همهٔ endpointها را غیرفعال
می‌کند؛ فعال‌سازی دوباره تصمیم صریح اپراتور است.

CA ده‌ساله و گواهی دستگاه/سرور یک‌ساله‌اند. گواهی سرور در هفت روز پایانی
خودکار با همان CA تمدید می‌شود؛ این تغییر اتصال مجدد می‌خواهد. گواهی دستگاه
نیازمند rotation و دریافت فایل جدید است. پیش از پایان CA، endpoint تازه
بسازید؛ تعویض خودکار CA و تمدید خودکار پروفایل خصوصی دستگاه ارائه نمی‌شود.

## محدودهٔ شبکه و پذیرش

داده و آدرس بیرونی فعلاً IPv4 هستند. پروفایل full-tunnel، IPv6 را داخل تونل
هدایت و مسدود می‌کند تا اتصال فعال از IPv6 فیزیکی نشت نکند؛ IPv6 سرویس
نمی‌شود. این تنظیم kill switch سیستم‌عامل نیست: بعد از خروج کلاینت، مسیر
فیزیکی معمول برمی‌گردد. پشتیبانی گزینه‌ها را در کلاینت مقصد بررسی کنید.
DNS صادرشده `dhcp-option` است؛ Linux CLI برای اعمال resolver به یکپارچه‌سازی
مناسب سیستم نیاز دارد. DNS به‌تنهایی تضمین عبور UDP بازی یا رفع تحریم نیست.

آزمون `tests/openvpn_acceptance.py --protocol udp` و حالت `tcp`، دو کلاینت
واقعی OpenVPN 2.6 را در Docker ایزوله اجرا می‌کند: TCP و UDP داخلی، عدم نشت
IPv6 هنگام اتصال، حسابداری/تکرار گزارش، رد CA و نام اشتباه، سریال قدیمی پس
از rotation، قطع جریان باز با حفظ دستگاه دیگر، cleanup آفلاین، restart،
سهمیه، دوره، انقضا و restore. گزینهٔ `--no-build` فقط OS/dependencies را
بازیافت می‌کند؛ سورس فعلی همیشه از inventory مجاز کپی می‌شود. این شاهد
آزمایشگاهی جای آزمون VPS، شبکهٔ ایران/خارج، بازی و بار عملیاتی را نمی‌گیرد.
