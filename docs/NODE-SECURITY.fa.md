# ثبت و نگهداری امن نود — پیش‌نمایش ۱.۰ آلفا ۴

این نسخه ثبت یک‌بارمصرف، mTLS، تمدید گواهی، امضای تنظیمات و محدودیت اجرای تنظیمات قدیمی را به عامل Xray اضافه می‌کند. سهمیهٔ اشتراکی مبتنی بر lease هنوز بخش جداگانهٔ در حال توسعهٔ فاز ۳ است؛ امضای تنظیمات به‌تنهایی سهمیهٔ جهانی دقیق ایجاد نمی‌کند.

## کنترل‌پنل

کنترل‌پنل را با نصب‌کنندهٔ native این نسخه روی همان دامنه نصب یا ارتقا دهید. نصب‌کننده CA مخصوص نود، کلید امضای تنظیمات و تنظیمات NGINX را ایجاد می‌کند. کلید `DONINO_PROXY_KEY` در محیط خصوصی پنل و snippet خصوصی پراکسی قرار می‌گیرد؛ headerهای گواهیِ ارسالی از اینترنت همیشه در NGINX بازنویسی می‌شوند. اپلیکیشن فقط گواهی‌ای را می‌پذیرد که NGINX اعتبار TLS آن را تأیید کرده و headerهایش از پراکسی خود نصب رسیده باشند. رابط مدیر همچنان بدون گواهی کلاینت در دسترس است.

نصب دستیِ قدیمی با افزودن صرف چند header امن نمی‌شود. تا وقتی مسیر پراکسی معتبر تنظیم نشده، تولید توکن ثبت امن رد می‌شود. Uvicorn را مانند الگوی نصب فقط روی loopback نگه دارید. کلید خصوصی CA یا کلید مشترک پراکسی را به نودها ندهید.

## ثبت یک نود

مالک در صفحهٔ نودها «ثبت امن نود» را می‌زند. توکن ۱۰ دقیقه اعتبار دارد؛ تولید توکن جدید، توکن ثبتِ قبلی همان نود را باطل می‌کند. توکن فقط همان بار نمایش داده می‌شود و مقدار خام آن در DB ذخیره نمی‌شود.

روی سرور نود، سورس و محیط Python همین نسخه و Xray پین‌شده طبق راهنمای deployment لازم‌اند؛ این مرحله هنوز نصب خودکار نقش node نیست. عامل قبلی را متوقف کنید، توکن را در فایل خصوصی با مالکیت کاربر سرویس و mode `0600` قرار دهید و از ریشهٔ سورس اجرا کنید:

```bash
sudo systemctl stop donino-node
cd /opt/donino-panel
sudo -u donino .venv/bin/python -m agent.enroll \
  --panel https://panel.example.com --node-id NODE_UUID \
  --state /var/lib/donino-node --token-file /secure/enrollment.token
sudo systemctl start donino-node
```

دامنه، UUID و مسیر فایل را با مقادیر واقعی جایگزین کنید. مسیر فایل باید برای کاربر `donino` قابل خواندن باشد؛ توکن را در آرگومان خط فرمان یا issue قرار ندهید. `--token-stdin` نیز برای جریان ورودی امن وجود دارد. پس از ثبت موفق، فایل توکن دیگر لازم نیست. برای CA خصوصیِ سرور پنل، `--ca-file` موقع ثبت و `DONINO_PANEL_CA_FILE` در محیط سرویس لازم‌اند؛ بررسی TLS خاموش نمی‌شود.

کلید P-256 روی نود ساخته و پیش از ارسال CSR خصوصی ذخیره می‌شود؛ پنل کلید خصوصی نود را دریافت نمی‌کند. هویت نود، گواهی و کلید عمومی امضای تنظیمات به‌صورت یک مجموعه در state نگه‌داری می‌شوند. پاسخ گم‌شده را می‌توان با همان توکن و همان CSR دوباره دریافت کرد؛ یک توکن نمی‌تواند CSR دوم یا هویت دوم صادر کند. فایل journal از پنل یا نود دیگری پذیرفته نمی‌شود.

ثبت موفق حالت نود را به `mtls` تغییر می‌دهد و bearer قدیمی بلافاصله رد می‌شود. حذف فایل گواهی از نود به معنی فعال‌شدن دوبارهٔ bearer نیست. دستگاه‌های VPN و لینک‌های اشتراک کاربر تغییر نمی‌کنند؛ این هویت مخصوص ارتباط مدیریتی عامل است.

## تمدید، ابطال و تنظیمات امضاشده

گواهی نود ۱۴ روز عمر دارد. عامل از هفت روز مانده به پایان، با هویت فعلی و CSR/کلید تازه تمدید می‌کند. گواهی قبلی حداکثر ۱۰ دقیقه برای تکمیل جابه‌جایی اعتبار دارد؛ بیش از یک هویت قبلی هم‌زمان نگه‌داری نمی‌شود. گواهی منقضی یا گم‌شده با توکن تازهٔ مالک دوباره ثبت می‌شود. تمدید از bearer مجاز نیست.

«ابطال گواهی نود» همهٔ گواهی‌ها و توکن‌های ثبتِ معوق آن نود را در API باطل می‌کند. عامل پس از 401/403 هسته را متوقف می‌کند. اگر شبکه قطع باشد، نگهبان مستقلِ عامل در پایان پنجرهٔ اجرای امضاشده هسته را متوقف می‌کند؛ اجرای عملیات HTTP مانع این نگهبان نیست. خاتمهٔ process ممکن است تا مهلت terminate/kill آن طول بکشد. این ابطال در مسیر API اعمال می‌شود؛ CRL عمومی TLS ادعا نشده است.

تنظیمات با Ed25519 امضا می‌شوند و شامل هویت نود، شمارهٔ ترتیبی پایدار، زمان صدور و اعتبار حداکثر ۶۰ ثانیه‌اند. عاملِ ثبت‌شده کلید عمومی را از ثبتِ HTTPS پین می‌کند، sequence را روی دیسک نگه می‌دارد و تغییر محتوا/نود، برگشت sequence، پیام منقضی یا اختلاف ساعت نامعتبر را رد می‌کند. دریافت candidate نامعتبر یا ناموفق، زمان اجرای تنظیمات قبلی را تمدید نمی‌کند. ساعت کنترل‌پنل و نود باید همگام باشد.

عامل legacy برای مهاجرت تدریجی همچنان bearer قدیمی را تا قبل از ثبت امن می‌پذیرد و به‌طور خودکار صاحب ادعای mTLS/امضای پین‌شده نمی‌شود. برای rollout، کنترل‌پنل را اول و هر نود را جداگانه بعد از آن ارتقا دهید.

## بازیابی

bundle کامل رمزگذاری‌شده اکنون CA نود و کلید امضای تنظیمات را نیز شامل می‌شود. بازیابی کنترل‌پنل روی DB خالی، کلیدهای همان شبکه را برمی‌گرداند و NGINX را با CA بازیابی‌شده reload می‌کند؛ پنل با دامنه و رمز DB مقصد باقی می‌ماند. کلید خصوصی نودها در این bundle نیست و باید روی میزبان نود حفظ شود. نودِ از دست‌رفته به ثبت مجدد مالک نیاز دارد.

اگر material خصوصی کنترل‌پنل ناقص یا حذف شده باشد، برنامه از تعویض پنهان ریشهٔ اعتماد جلوگیری می‌کند؛ کلیدها را از backup متناظر برگردانید. CA عمومی و کلید خصوصی جفت‌ناهمسان پذیرفته نمی‌شوند. fixture پذیرش، بازیابی CA و امضاکننده و ادامهٔ احراز هویت گواهی قبلی را در میزبان دوم آزمایش می‌کند؛ VPS عمومی و صدور واقعی ACME همچنان gate جدا هستند.
