# نصب و منوی Donino — v1.0.0

## منوی مستقل

فرمان README سورس نسخهٔ مشخص را با checksum دانلود می‌کند و منوی
`DONINO PANEL / SETUP & MANAGEMENT` را در alternate screen ترمینال باز می‌کند؛
خروج یا Ctrl-C صفحهٔ قبلی را بازمی‌گرداند. هنگام curl-pipe، صفحه‌کلید از
`/dev/tty` خوانده می‌شود. `TERM=dumb` نمایش ساده و `NO_COLOR` نمایش بدون رنگ
دارد. نصب دارای سرویس systemd روی Debian12/Ubuntu24 amd64 پشتیبانی می‌شود؛
در ترمینال SSH با دسترسی sudo اجرا کنید. محیط non-interactive باید flagهای
نصب مستقیم را بدهد؛ منو از ورودی بسته، پاسخ فرضی یا تأیید خودکار نمی‌سازد.

اگر curl روی تصویر حداقلی موجود نیست ابتدا بستهٔ رسمی `curl` را نصب کنید.
خود اسکریپت نبود Python یا CA bundle را با apt برطرف می‌کند؛ سپس manifest
آرشیو و تمام فایل‌های محصول را پیش از import بررسی می‌کند. برنامه و نیازمندی‌های
قفل‌شده در release مستقل آماده می‌شوند. PostgreSQL و NGINX و کاربر محدود
برنامه، schema، سرویس، backup رمزگذاری‌شده و اولین دسترسی یک‌بارمصرف آماده
می‌شوند. وضعیت مراحل با پیام‌های ثابت و فایل خصوصی state ثبت می‌شود.

بعد از نصب: `sudo donino`. فرمان نصب‌شده از همان محیط قفل‌شده و release فعال
استفاده می‌کند. گزینهٔ upgrade یک tag یا SHA کامل می‌گیرد؛ شاخهٔ متحرک و
فرمان shell دلخواه پذیرفته نمی‌شود. انتخاب دوبارهٔ همان نسخه reinstall است.

## بدون SSL

گزینهٔ ۱ منو یا `install --tls none --domain IPV4_OR_DOMAIN`، HTTP روی پورت
۸۰ را فعال می‌کند. IPv4 نیازی به دامنه یا گواهی ندارد؛ دامنهٔ HTTP باید به
همین سرور اشاره کند. IPv6 literal فعلاً ارائه نمی‌شود؛ دامنه با AAAA و
میزبان دارای IPv6 پذیرفته می‌شود. HTTPS هنوز دامنه می‌خواهد؛ IP certificate
خودکار در این برش پشتیبانی نشده است.

HTTP، رمز مدیر و session cookie را روی شبکه رمز نمی‌کند. این انتخاب، قرارداد
HTTPS/mTLS ثبت و ارتباط نود دوردست را خاموش نمی‌کند. از alpha19، DNS معمولی UDP/TCP با گزینه۱۰ و `--with-dns` در HTTP نصب می‌شود؛
DoH لازم نیست و DoT در این حالت خاموش است. گزینه‌های گواهی با HTTP رد می‌شوند.
Smart DNS جلوی TLS/SNI نیز بدون گواهی پنل قابل فعال‌کردن است؛ قرارداد TLS/auth
خروجی خودش حفظ می‌شود. [راهنما](PLAIN-DNS.fa.md).
Certbot در حالت HTTP پیش‌نیاز نیست و بدون گواهی، repair یا renew جعلی انجام
نمی‌شود. کانفیگ NGINX نه redirect به HTTPS دارد نه ارجاع به فایل گواهی ناموجود.

نصب مجدد، mode و host را از state می‌خواند؛ `install` بدون flag منو نیست و
همان نصب را ادامه می‌دهد. صاحب پنل، کاربران، حجم، دیتابیس و کلیدها reset
نمی‌شوند. `repair` برای HTTP گواهی نمی‌خواند. تغییر host یا TLS mode نصب موجود
فعلاً migration مستقل می‌خواهد و پیش از تغییر سرویس رد می‌شود؛ HTTPS تازه
را با گزینهٔ ۲ در نصب تازه تنظیم کنید. این منو تغییر mode نصب موجود را
به‌عنوان قابلیت پنهان ادعا نمی‌کند.

## گواهی خودکار

گزینهٔ ۲ دامنه و ایمیل اختیاری می‌گیرد. A/AAAA باید با IP تشخیص‌داده‌شده یا
`--expected-ip` تطبیق کند و TCP80/443 عمومی باز باشد. NGINX وب‌روت چالش را
سرو می‌کند؛ Certbot رسمی توزیع، با نام ثابت `donino-panel` و
`--keep-until-expiring` گواهی می‌گیرد. reinstall بدون دلیل گواهی تازه صادر
نمی‌کند. نصب‌کننده firewall، SSH یا resolver موجودِ نامرتبط را پاک نمی‌کند.

pair و نام دامنه و اعتبار گواهی پیش از اعمال بررسی می‌شوند؛ مسیر نهایی
`/etc/donino/tls/panel.crt` و `panel.key` است. certbot.timer تمدید را اجرا
می‌کند؛ deploy hook به `renew-certificate` همان release فعال می‌رسد و بعد از
اعتبارسنجی، NGINX را check/reload می‌کند. شکست reload زوج قبلی را برمی‌گرداند.
خطای صدور، مجوز افتادن خودکار به HTTP نیست. DNS-01/provider و دستکاری خودکار
firewall ارائه نشده‌اند. صدور عمومی روی دامنهٔ کاربر هنوز آزمایش نشده است.

گزینهٔ ۳ گواهی موجود و مسیرهای مطلق را می‌گیرد. CA خصوصی اختیاری بعد از
بررسی گواهی در مسیر ثابت trust نگهداری می‌شود تا repair/upgrade به حذف فایل
موقت کاربر وابسته نباشند؛ verification خاموش نمی‌شود. نصب‌های HTTPS قدیمی
فاقد `tls_mode` به‌اشتباه ACME فرض نمی‌شوند و همان `--tls existing` را می‌پذیرند.

لینک اولیه حاوی راز است و در فایل خصوصی
`/var/lib/donino-installer/bootstrap-access.txt` قرار می‌گیرد؛ در گفتگو/Git
منتشر نکنید. `bootstrap` بعد از وجود مالک، دسترسی تازه نمی‌سازد. uninstall
فقط فایل‌ها و سرویس‌های managedِ دست‌نخورده را حذف و داده/کلید/backup را حفظ
می‌کند؛ تغییر محلی فایل managed نیازمند بررسی اپراتور است.

## معماری مرجع و شواهد

کد shell این پروژه‌ها ترکیب نشده است؛ پیاده‌سازی مستقل با الهام از منوی
نصب و چرخهٔ صدور→ذخیرهٔ مسیر ثابت→reload پس از تمدید انجام شد:

- [3x-ui install](https://github.com/MHSanaei/3x-ui/blob/608ef4e4010bf83e2e78328e08f77efc051ad4d7/install.sh): انتخاب صدور، چالش پورت۸۰ و reloadcmd.
- [PasarGuard scripts](https://github.com/PasarGuard/scripts/blob/bba95f274216968542497a500c74a06802c48e88/pasarguard.sh): تشخیص پیش‌نیاز ACME، نصب pair در مسیر ثابت و دستور reload سرویس.

در دونینو از Certbot بستهٔ رسمی و چالش webroot روی NGINX استفاده می‌شود؛
TLS verification، backup، manifest و state موجود حفظ شده‌اند. این آزمایش‌ها
بررسی نسخه‌های اشاره‌شده‌اند و ادعای کپی همهٔ امکانات آن دو پنل نیستند.

`native_http_acceptance.py` روی دو OS، HTTP/IP، NGINX/systemd/PostgreSQL واقعی،
bootstrap/login/cookie، ساخت حساب و کلید رمز‌شده، reinstall بدون flags، repair،
حفظ owner/quota/کلید، launcher نصب‌شده در PTY واقعی با stdin قطع و uninstall
حافظ داده را بررسی می‌کند. fixture HTTPS موجود همچنان mTLS/renewal/restore و
DNS/Smart DNS را با CA محلی می‌سنجد؛ این‌ها جای VPS، ACME عمومی و ISP را نمی‌گیرند.
