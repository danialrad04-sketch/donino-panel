# دفتر همکاری Codex و Claude

این پوشه حافظهٔ مشترک پروژه است. `CLAUDE.md` در ریشه، دستور شروع هر جلسهٔ Claude Code است؛ در ابزارهایی که آن را خودکار نمی‌خوانند، یک‌بار به کلاد بگو «ابتدا CLAUDE.md همین مخزن را بخوان». پس از آن «ادامه» یعنی ادامهٔ مأموریت ثبت‌شده، نه شروع دوبارهٔ همهٔ فازها. پیام‌های دو گفت‌وگو خودکار به یکدیگر نمی‌رسند.

## تقسیم مسئولیت فعلی

به دستور تازهٔ کاربر، کلاد فعلاً `suspended` است و Codex کار را ادامه می‌دهد؛ مأموریت جدید برای کلاد تا دستور بعدی کاربر تعیین نمی‌شود. `status --actor claude` این توقف را نشان می‌دهد و نوشتن checkpoint تازه برای او را رد می‌کند. `check` همهٔ مجری‌ها را بررسی می‌کند؛ وضعیت فعال با `status --actor codex` در دسترس است.


`assignments.json` را Codex برای تعیین مأموریت به‌روز می‌کند. فایل task قرارداد کار است؛ checkpoint را همان مجری روی شاخهٔ خودش به‌روز می‌کند. Codex شاخه/PR کلاد را fetch و بازبینی می‌کند، نتیجه را در PR و مأموریت بعدی ثبت می‌کند. اتمام کلاد به معنی merge یا تأیید نیست. در پایان مأموریت، وضعیت `waiting_for_review` است و تا بازخورد یا مأموریت بعدی، کار تازه‌ای انتخاب نمی‌شود.

Git، push غیر اجباری و PR مرز هم‌زمانی‌اند. این فایل‌ها قفل توزیع‌شده نیستند. در push ردشده ابتدا fetch و اختلاف را بررسی کن؛ checkpoint طرف مقابل را overwrite نکن. انتساب تازه باید روی main منتشر شود؛ checkpoint در شاخهٔ task باقی می‌ماند و از PR در دسترس Codex است. اگر شبکه قطع است، checkpoint محلی ذخیره کن و صریح بنویس که هنوز push نشده است.

## نقطهٔ ادامه

وضعیت‌ها: `assigned` → `in_progress` → `waiting_for_review`؛ مانع واقعی می‌تواند `blocked` باشد. Codex پس از بازبینی task را تکمیل یا با بازخورد دوباره فعال می‌کند. با نزدیک‌شدن به لیمیت، فقط وعدهٔ ذخیره نده: فایل، commit و push را انجام بده. قطع ناگهانی ممکن است بین دو checkpoint رخ دهد؛ جلسهٔ بعد باید diff و تاریخچه را هم بررسی کند.

```sh
python scripts/coordination.py status --actor claude
python scripts/coordination.py check
```

قالب ورودی checkpoint، بدون رمز یا کد جفت‌سازی:

```json
{
  "task_id": "mihomo-tls-acceptance-v1",
  "status": "in_progress",
  "branch": "claude/mihomo-tls-acceptance-v1",
  "last_verified_commit": null,
  "completed": ["اعتبارسنجی transportها تکمیل شد"],
  "remaining": ["آزمون انتقال واقعی چهار مسیر"],
  "next_action": "آزمون tests/test_xray_transports.py را تکمیل و اجرا کن",
  "tests": [],
  "blockers": [],
  "pr_url": null
}
```

این JSON را در فایل موقت بنویس و به ابزار `checkpoint --actor claude --input PATH` بده. ابزار قالب و ارتباط با task را اعتبارسنجی و اتمیک ذخیره می‌کند؛ هیچ فرمانی از `next_action` اجرا نمی‌کند. `last_verified_commit` فقط SHA کدی است که واقعاً آزموده شده؛ اگر هنوز هیچ commit آزموده نشده، null بماند. آزمونِ ردشده/skipشده را صریح در `tests` بنویس. ابزار مانع قطعی ثبت همهٔ انواع راز نیست؛ مجری مسئول بازبینی محتوا قبل از commit است.

فرمان checkpoint، manifest سورس را هم به‌روز می‌کند؛ هر دو فایل باید در commit قرار گیرند. اگر بعد از آن فایل محصول یا مستندات را تغییر دادی، دوباره `python scripts/release_manifest.py` را اجرا کن. JSON ورودی نامعتبر قبل از نوشتن رد می‌شود. ذخیرهٔ دو فایل یک تراکنش مشترک فایل‌سیستم نیست؛ خطای نوشتن را بررسی کن و پیش از push حتماً `--check` را اجرا کن.

## جریان موازی و تحویل

چهار transport در PR ۱۳ تحویل و ادغام شدند. پذیرش افزوده در PR ۱۵ تحویل و [بازبینی](reviews/xray-acceptance-v1.fa.md) شد. آخرین مأموریت کلاد [کلاینت واقعی Mihomo](tasks/mihomo-tls-acceptance-v1.fa.md) بود که Codex آن را در PR ۱۷ تکمیل کرد؛ [ادامهٔ فعال](tasks/codex-v1-progress.fa.md) با Codex است. [بازبینی مأموریت قبلی](reviews/xray-transports-v1.fa.md) ثبت شده است. Codex: هماهنگی، بازبینی، DNS/relay و اتصال Donino Tunnel. فایل‌های مشترک از جمله `app/main.py` و `app/static/app.js` فقط با diff محدود تغییر می‌کنند؛ کل فایل جایگزین نمی‌شود. اگر برخورد ایجاد شد، تغییر task را جدا نگه دار و وابستگی را در PR ثبت کن.

محیط فعلی آزمایشی است؛ VPS/دامنهٔ کاربر فراهم نشده است. لیمیت سرویس Claude از این مخزن قابل دورزدن یا بازنشانی نیست. ادامه با پیام کاربر، از آخرین commit/checkpoint بازیابی می‌شود؛ تضمین بازیابی کار ذخیره‌نشده ممکن نیست.
