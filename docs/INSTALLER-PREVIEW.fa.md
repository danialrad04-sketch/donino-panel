# راهنمای نصب آزمایشی ۱.۰ alpha 7

این نصب‌کننده **نقش کنترل‌پنل** و با گزینهٔ `--with-dns`، [resolver و gateway DNS روی همان میزبان](DNS-PREVIEW.fa.md) را نصب می‌کند. DNS relay/exit و موتورهای تازه همراه فازهای بعد تکمیل می‌شوند. هدف OS: Debian 12 و Ubuntu 24.04 روی amd64 با systemd و Python 3.11+. آزمون نصب/بازیابی در کانتینرهای جدا با systemd انجام شده است؛ VM، VPS عمومی و صدور واقعی Let’s Encrypt هنوز شاهد پذیرش ندارند. برای production، این برچسب آزمایشی را با انتشار پایدار اشتباه نگیرید.

## شروع از سورس همین شاخه

روی سرور تمیز، A و در صورت استفاده AAAA دامنه را به IPهای واقعی همان سرور تنظیم و TCP/80 و TCP/443 را از فایروال میزبان/ارائه‌دهنده قابل دسترس کنید. سپس:

```bash
git clone --branch v1.0.0-alpha.7 https://github.com/danialrad04-sketch/donino-panel.git
cd donino-panel
sudo ./install.sh --domain panel.example.com
```

نام نمونه را با دامنهٔ تحت اختیار خود جایگزین کنید. `plan --domain DOMAIN` طرح و پیش‌نیازهای خواندنی را گزارش می‌کند؛ کاری روی سرویس‌ها انجام نمی‌دهد. اگر IP عمومی از محیط قابل تشخیص نیست، `--expected-ip IP` را برای هر IPv4/IPv6 مورد انتظار بدهید. وجود یک AAAA اشتباه دلیل رد نصب است، نه حذف پنهان IPv6.

نصب شامل بسته‌های رسمی توزیع، کاربر محدود، PostgreSQL محلی، venv با نسخه‌های بستهٔ پین‌شده، schema، NGINX، مسیر ACME/تمدید، اولین مالک یک‌بارمصرف و backup رمزگذاری‌شده است. نسخهٔ واقعی بسته‌های OS از مخزن امضاشدهٔ همان توزیع تأمین می‌شود؛ major حرفه‌ای هدف فعلاً PostgreSQL 15/16 است. installer فایروال عمومی یا قوانین SSH را پاک نمی‌کند؛ بازبودن پورت provider را نمی‌تواند بدون دسترسی provider ایجاد کند.

کد محصول با `release-manifest.json` تطبیق داده می‌شود. فایل ناقص/دستکاری‌شده رد می‌شود. برای توسعهٔ محلیِ بدون manifest فقط `--development-source` صریح مجاز است؛ برای کد تغییرکرده، manifest را با `python scripts/release_manifest.py` بازتولید کنید. این checksum جای امضای ناشر یا ممیزی امنیتی را نمی‌گیرد؛ منبع مورد اعتماد همچنان همین مخزن/نسخه است.

## ساخت اولین مدیر

پس از موفقیت نصب، لینک راه‌اندازی در فایل خصوصی زیر قرار می‌گیرد:

```bash
sudo cat /var/lib/donino-installer/bootstrap-access.txt
```

لینک یک ساعت اعتبار دارد، token در fragment مرورگر است و پس از خواندن از نشانی جاری پاک می‌شود. در صفحه، نام کاربری و رمز خود را تعیین کنید؛ رمز مشترک/پیش‌فرض وجود ندارد. پس از ایجاد اولین مدیر، bootstrap برای همیشه تا وقتی هر مدیر موجود است بسته می‌شود. لینک را در issue، تصویر یا پیام عمومی قرار ندهید.

اگر لینک پیش از ایجاد اولین حساب منقضی شد:

```bash
sudo ./install.sh bootstrap
```

این دستور با وجود حساب مدیر اجازهٔ ساخت مالک جدید نمی‌دهد. تغییر رمز حساب موجود همچنان از CLI مدیریت با محیط نصب‌شده انجام می‌شود؛ `bootstrap` مسیر دورزدن MFA نیست.

## گواهی و نصب دوباره

ACME پیش‌فرض HTTP-01/webroot است. `--email EMAIL` اختیاری است؛ بدون ایمیل حساب ACME بدون نشانی اعلان ساخته می‌شود. `--acme-staging` فقط آزمایش CA است و گواهی آن برای مرورگر عمومی معتبر نیست. wildcard/DNS-01 provider هنوز در این برش نصب‌کننده پیاده نشده است؛ می‌توان گواهی معتبرِ تهیه‌شده را با حالت existing نصب کرد.

```bash
sudo ./install.sh --domain panel.example.com --tls existing \
  --cert-file /secure/fullchain.pem --key-file /secure/privkey.pem
```

chain، hostname، expiry و تطابق key بررسی می‌شوند. `--ca-file` فقط برای اعتماد صریح به CA خصوصی، مثلاً آزمایش محلی، است؛ بررسی TLS را خاموش نمی‌کند. نصب روی دامنهٔ دیگر، adoption سرویس دستی یا تصاحب NGINX نامرتبط خودکار نیست. برای افزودن vhost به NGINX موجود، بعد از بررسی طرح می‌توان `--allow-existing-nginx` داد. دادهٔ قبلی بدون وضعیت نصبِ managed باید با migration صریح منتقل شود.

اجرای دوباره همان فرمان کلید و DB را reset نمی‌کند. قبل از انتخاب نسخه جدید، backup گرفته می‌شود؛ migration با کد candidate و سرویس متوقف انجام می‌شود. شکست پس از تغییر schema، مجوز اجرای خودکار باینری قدیمی روی دادهٔ جدید نیست؛ DB، کلیدها و کد متناظر باید با هم بازیابی شوند.

## نگهداری و پشتیبان

```bash
sudo ./install.sh doctor
sudo ./install.sh backup
sudo ./install.sh repair
```

`doctor` وضعیت نصب و آمادگی API/DB را بدون نمایش secret گزارش می‌کند. `repair` تنظیمات متعلق به همین نصب را بررسی و سرویس را دوباره راه‌اندازی می‌کند؛ اصلاح خودکار schema ناسازگار یا تنظیمات شبکهٔ نامرتبط نیست. برای CA خصوصی، همان `--ca-file` لازم است. `/healthz` زنده‌بودن process و `/readyz` اتصال DB را گزارش می‌دهند؛ هیچ‌یک اثبات سلامت تمام تونل‌های نود نیستند.

backup روزانه با systemd timer و یک backup اولیه ایجاد می‌شود. فایل‌های `.dnb` با AES-256-GCM و nonce تصادفی، به‌صورت جریان رمزگذاری و احراز اصالت می‌شوند. شامل snapshot سازگار DB، تنظیم پنل، گواهی/کلید پنل در صورت وجود، master key مربوط به MFA و وضعیت installer هستند. دادهٔ نودهای جدا یا کل ماشین در این bundle نیست.

**کلید `/etc/donino/backup.key` را جدا از backup و خارج از همان سرور نگه دارید.** از دست رفتن هم‌زمان backup و کلید روی همان دیسک قابل بازیابی نیست. فایل DB دانلودی داخل UI همچنان backup خصوصی DB است و به‌تنهایی کلید MFA/تنظیمات میزبان را شامل نمی‌شود. انتقال فایل‌های رمزگذاری‌شده به مقصد خارجی و retention در فاز عملیات تکمیل می‌شود؛ ظرفیت دیسک تا آن زمان باید پایش شود.

## بازیابی روی میزبان تازه

نسخهٔ سازگار پنل را نصب کنید و پیش از ایجاد هر مدیر، backup و کلید جداگانه را با دسترسی خصوصی به مقصد بیاورید. ابتدا فقط بررسی:

```bash
sudo ./install.sh restore --archive /secure/control.dnb \
  --backup-key-file /secure/backup.key
```

سپس اعمال در DB **خالی**:

```bash
sudo ./install.sh restore --archive /secure/control.dnb \
  --backup-key-file /secure/backup.key --apply
```

داده پیش از قطع سرویس احراز اصالت می‌شود؛ restore به DB غیرخالی رد می‌شود. DB و MFA key متناظر بازیابی، و sessionها/API tokenهای مدیریتی قدیمی باطل می‌شوند. اعتبارنامه و اشتراک کاربران حفظ می‌شوند. رمز DB، دامنه و TLS مقصد خودکار با تنظیمات میزبان قبلی جایگزین نمی‌شوند؛ دامنه/سرور تازه باید وضعیت معتبر خودش را داشته باشد. ابزار تا آماده‌شدن API/DB صبر می‌کند و سپس موفقیت را گزارش می‌دهد.

## حذف سرویس

```bash
sudo ./install.sh uninstall
```

فقط واحدها و تنظیمات ثبت‌شدهٔ خود Donino حذف می‌شوند؛ فایل با تغییر دستی بدون تطبیق حذف نمی‌شود. DB، account، کلید، نسخه‌های کد و backup نگه داشته می‌شوند. حذف کامل داده، توقف PostgreSQL عمومی میزبان یا پاک‌کردن فایروال بخشی از این دستور نیست.

این شاخه بر schema نسخهٔ main (نسخهٔ ۷) ادامه یافته است. بازیابی bundle باید با همان schema و همان backend انجام شود؛ انتقال SQLite به PostgreSQL یا بازیابی bundle شاخهٔ قدیمی development/1.0 در این مسیر پشتیبانی نمی‌شود.

در آلفا ۴، CA مخصوص نود، کلید امضای تنظیمات و پراکسی mTLS نیز نصب می‌شوند؛ راهنمای [امنیت نود](NODE-SECURITY.fa.md) را برای ثبت عامل و مهاجرت بخوانید.
