# DNS معمولی با IP — alpha.19

DNS روی UDP/TCP53 به دامنه، DoH، گواهی یا SSL پنل نیاز ندارد. پنل مدیریت می‌تواند
HTTP با IP باشد. DoH یک روش اختیاری انتقال درخواست DNS روی HTTPS است و مسیر
اصلی اتصال کنسول/کامپیوتر در این نسخه نیست.

## نصب و استفاده

۱. نصب موجود را به `v1.0.0-alpha.19` ارتقا دهید: `sudo donino`، گزینه۷ و tag نسخه.
ابتدا پشتیبان رمزگذاری‌شده بگیرید. سپس گزینه۱۰، «Enable plain DNS» را انتخاب
کنید و **IP اختصاص‌یافته به خود سرور** را بدهید. روی نصب تازه ابتدا HTTP/IP
را با گزینه۱ نصب کنید. DNS فقط با ساخت حساب در وب نصب نمی‌شود.

۲. نصب‌کننده Unbound معتبرِ loopback و gateway روی IP انتخابی، UDP/TCP53 را
آماده می‌کند. در حالت HTTP، DoT خاموش است و گواهی ساخته یا خوانده نمی‌شود.
خدمت DNS یا resolver نامرتبط متوقف نمی‌شود؛ تداخل پورت باعث توقف نصب با خطا
می‌شود. firewall سیستم/شرکت میزبان خودکار تغییر نمی‌کند؛ اپراتور باید UDP53
و TCP53 را برای مشتری‌های موردنظر در دسترس قرار دهد.

۳. در بخش DNS پنل، سیاست دامنه بسازید؛ سیاست بدون قاعده از resolver استفاده
می‌کند. برای دامنه‌های منتخب کاتالوگ سرویس‌ها یا قواعد دقیق‌تر موجودند. DNS را
برای کاربر فعال و سهمیهٔ درخواست و نرخ را تعیین کنید. انقضا و غیرفعال‌شدن خود
کاربر هم بر خدمت DNS اثر دارد؛ سهمیهٔ DNS مستقل از حجم VPN است.

۴. در «IPهای مجاز»، **IP اینترنت مشتری** را ثبت کنید؛ این با IP سرور DNS فرق دارد.
IPv4 و IPv6 پذیرفته می‌شوند. هر حساب حداکثر سه IP فعال دارد؛ IP مشترک هم‌زمان
به دو حساب منتسب نمی‌شود. ثبت مجدد همان IP اعتبارش را تمدید می‌کند. IP خصوصی
یا loopback فقط با انتخاب صریح مدیر برای LAN/آزمایش قابل ثبت است؛ پرتال مشتری
همچنان فقط IP عمومی همان اتصال را می‌پذیرد و هدر دلخواه XFF را باور نمی‌کند.

۵. در تنظیمات DNS کنسول/گوشی/کامپیوتر، IP سرور را وارد کنید؛ username، رمز و
نشانی `dns-query` لازم نیست. کنسول‌ها معمولاً پورت سفارشی نمی‌پذیرند و ۵۳
می‌خواهند. DNS دوم باید نشانی مجاز دیگری از زیرساخت خودتان باشد؛ resolver
ثالث ممکن است انتخاب دامنه و سیاست را دور بزند. بعد از عوض‌شدن IP اینترنت،
IP جدید را ثبت کنید یا در پرتال خصوصی «ثبت IP همین اتصال» را بزنید.

نصب مستقیم برای نمونهٔ سرور با IP واقعیِ جایگزین‌شده:

```sh
curl -fsSL https://raw.githubusercontent.com/danialrad04-sketch/donino-panel/v1.0.0-alpha.19/install.sh | sudo sh -s -- install --domain 203.0.113.10 --tls none --with-dns --dns-listen 203.0.113.10 --dns-port 53 --dot-port 0
```

IP باید روی میزبان قابل bind باشد. در NAT، نشانی عمومی ممکن است روی NIC موجود
نباشد؛ این فرمان جای تنظیم NAT اپراتور را نمی‌گیرد. bind به loopback فقط
مشتری محلی می‌پذیرد؛ 0.0.0.0 آدرس قابل واردکردن در دستگاه مشتری نیست.

## DNS و رفع تحریم

DNS عادی فقط پاسخ نام دامنه را می‌دهد؛ تغییر محل resolver به خارج، IP اتصال
HTTP/بازی را خودبه‌خود عوض نمی‌کند. برای رفع محدودیت مبتنی بر IP مقصد، مسیر
relay هم لازم است. قواعد route، IP جلویی مجاز را فقط در صورت gateway آماده،
حساب/lease/سهمیه و خروجی مجاز منتشر می‌کنند؛ این با rewrite سادهٔ IP فرق دارد.

در alpha19 جلوی TLS/SNI پورت۴۴۳ می‌تواند کنار پنل HTTP کار کند و به گواهی
دامنهٔ پنل نیاز ندارد. TLS سرویس اصلی مشتری به مقصد بدون دستکاری عبور می‌کند؛
ارتباط احرازشده و TLS معتبر به exit دونینو حفظ شده است. این مسیر DoH مشتری نیست.
آماده‌سازی exit مستقل هنوز قرارداد گواهی/احراز هویت خودش را دارد؛ واردکردن IP
خارج به‌تنهایی نصب یا پذیرش آن exit را انجام نمی‌دهد. HTTP دانلود CDNs روی۸۰،
UDP دلخواه بازی، ECH و همهٔ کنسول‌ها در این انتشار پشتیبانی اثبات‌شده ندارند.

## مرجع doctor-dns و شواهد

fork کاربر و منبع اصلی در commit
`a2b2ff843cb1fc8f0a5712a88149f5c379198ff1` بررسی شدند؛ HEAD fork هنگام بررسی همین
بود. [relay-nginx](https://github.com/danialrad04-sketch/doctor-dns/blob/a2b2ff843cb1fc8f0a5712a88149f5c379198ff1/templates/relay-nginx.conf)
پورت‌های۸۰/۴۴۳ را به IP خارج می‌فرستد،
[DNS service](https://github.com/danialrad04-sketch/doctor-dns/blob/a2b2ff843cb1fc8f0a5712a88149f5c379198ff1/templates/smartdns-dns%40.service)
از dnsmasq استفاده می‌کند و ACL/پنل آن ثبت IP مشتری را مدیریت می‌کنند. معماری
DNS معمولی، ثبت IP، دامنهٔ منتخب و جدایی DNS از relay مرجع بوده است؛ shell،
nftables و DB آن پروژه با دونینو مخلوط نشده‌اند. کاتالوگ MIT قبلی و نسبت‌دادن
منبع آن حفظ شده است. هر ادعای آن پروژه دربارهٔ شبکه/بازی، پذیرش دونینو نیست.

آزمون واقعی DNS بدون TLS، ثبت/حذف IP، سهمیه، بایت پاسخ و انقضای کاربر در
`test_plain_dns.py` موجود است. fixture نصب HTTP روی Debian12/Ubuntu24، DNS واقعی
پورت۵۳ با Unbound، نبود فایل گواهی، سهمیه، Smart gateway و نصب مجدد/repair/حذف
حافظ داده را می‌سنجد. مرورگر واقعی راهنمای بدون DoH و مدیریت IP را بررسی می‌کند.
این‌ها جای VPS/ISP/گوشی یا کنسول واقعی و آزمون ظرفیت را نمی‌گیرند؛ stable v1 نیست.
